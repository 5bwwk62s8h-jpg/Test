# Калькулятор ожидаемых затрат по ФОТ

В репозитории два приложения с общей бизнес-логикой:

- **`payroll_calculator/`** — консольная программа на Python (см. ниже);
- **`app/` + `domain/`** — нативное Android-приложение на Kotlin/Jetpack Compose,
  портирующее ту же логику расчёта (см. [раздел «Android-приложение»](#android-приложение)).

## Python CLI

Программа на Python для расчёта ожидаемых затрат по фонду оплаты труда (ФОТ)
за месяц с учётом:

- **нормы рабочего времени** — по упрощённому производственному календарю
  (40-часовая неделя, нерабочие праздничные дни, сокращение на 1 час
  предпраздничных рабочих дней);
- **отпусков** — оклад за отработанное время уменьшается пропорционально
  пропущенным рабочим часам, отдельно рассчитываются отпускные исходя из
  среднего дневного заработка и календарных дней отпуска (нерабочие
  праздничные дни в период отпуска не оплачиваются, ст. 120 ТК РФ);
- **премий** сотрудников — фиксированной суммой, процентом от оклада или
  процентом от начисления за фактически отработанное время;
- (опционально) **страховых взносов** работодателя — процент от начисленной
  суммы.

## Установка

Зависимостей вне стандартной библиотеки Python не требуется. Для запуска
тестов нужен `pytest`:

```bash
pip install pytest
```

## Использование

Список сотрудников описывается в JSON-файле (пример — `examples/employees.json`):

```json
[
  {
    "id": "1",
    "name": "Иванова Анна Сергеевна",
    "oklad": 120000,
    "rate": 1,
    "vacations": [
      {"start": "2026-08-10", "end": "2026-08-23"}
    ],
    "premium_type": "percent_worked",
    "premium_value": 20,
    "avg_daily_earning": 3800
  }
]
```

Поля:

| Поле | Обязательно | Описание |
|---|---|---|
| `id`, `name` | да | Идентификатор и имя сотрудника |
| `oklad` | да | Оклад за полную норму при ставке 1.0 |
| `rate` | нет (по умолч. 1) | Ставка: 0.5, 1.0, 1.5 и т.д. |
| `vacations` | нет | Список периодов отпуска `{"start": "YYYY-MM-DD", "end": "YYYY-MM-DD"}` |
| `premium_type` | нет (`fixed`) | `fixed` — фикс. сумма, `percent_oklad` — % от оклада, `percent_worked` — % от начисления за отработанное время |
| `premium_value` | нет (0) | Сумма или процент премии, в зависимости от `premium_type` |
| `avg_daily_earning` | нет | Средний дневной заработок для расчёта отпускных. Если не указан, оценивается как `oklad * rate / 29.3` |

Запуск расчёта за текущий месяц:

```bash
python -m payroll_calculator.cli --employees examples/employees.json
```

Запуск за конкретный месяц, со страховыми взносами и выгрузкой в CSV:

```bash
python -m payroll_calculator.cli \
  --employees examples/employees.json \
  --year 2026 --month 8 \
  --insurance-rate 30.2 \
  --csv report.csv
```

Все опции CLI:

```
--employees PATH        JSON-файл со списком сотрудников (обязательно)
--year YEAR              Год (по умолчанию — текущий)
--month MONTH             Месяц 1-12 (по умолчанию — текущий)
--insurance-rate RATE    Ставка страховых взносов работодателя, % (по умолчанию 0)
--holidays PATH          Свой файл праздничных/предпраздничных дней
--csv PATH                Сохранить отчёт также в CSV
```

## Производственный календарь

Праздничные и предпраздничные дни хранятся в
`payroll_calculator/data/holidays_ru.json` для 2024-2027 годов и не
учитывают ежегодный перенос выходных дней постановлением Правительства РФ.
Для точного соответствия официальному производственному календарю на
конкретный год отредактируйте этот файл или передайте свой через
`--holidays путь/к/файлу.json` (формат такой же).

## Структура проекта

```
payroll_calculator/
  models.py               # Employee, VacationPeriod, PremiumType
  production_calendar.py  # норма часов/дней за месяц
  calculator.py            # расчёт затрат по сотруднику и по месяцу
  data_loader.py           # загрузка сотрудников из JSON
  report.py                # текстовый и CSV отчёт

  data/holidays_ru.json    # праздничные/предпраздничные дни
examples/employees.json    # пример входных данных
tests/                      # тесты pytest
```

## Android-приложение

Нативное приложение для телефона на Kotlin + Jetpack Compose + Room,
реализующее тот же расчёт ФОТ (норма часов, отпуска, премии, страховые
взносы), что и Python CLI, но с локальным хранением сотрудников на
устройстве и собственным UI на русском языке.

### Структура

```
domain/     — чистый Kotlin-модуль (без Android-зависимостей): порт
              production_calendar.py и calculator.py на Kotlin
              (ProductionCalendar, PayrollCalculator, Employee, ...),
              с тестами (domain/src/test) на те же сценарии, что и
              tests/test_calculator.py.
app/        — Android-модуль: Room (хранение сотрудников и периодов
              отпуска), Jetpack Compose UI (список сотрудников,
              редактирование, отчёт по месяцу с экспортом в CSV),
              Navigation-Compose, светлая/тёмная тема.
```

### Экраны

- **Сотрудники** — список, добавление/редактирование/удаление; для
  каждого — оклад, ставка, тип и размер премии, средний дневной заработок,
  периоды отпуска (выбираются датапикером).
- **Отчёт** — расчёт за выбранный месяц (стрелки листают месяцы), поле
  ставки страховых взносов, карточки с итогами и разбивка по каждому
  сотруднику; кнопка «Экспорт в CSV» делится файлом через системный диалог.

### Сборка

Проект открывается в Android Studio (Koala/Ladybug и новее) как обычно —
`File → Open` на корень репозитория. Требования: JDK 17+, Android SDK
(compileSdk 34), интернет-доступ к `google()`/`mavenCentral()` для
Gradle-зависимостей (Android Gradle Plugin, Compose, Room). Либо из
терминала на машине с установленным Android SDK:

```bash
./gradlew :app:assembleDebug
# APK: app/build/outputs/apk/debug/app-debug.apk
```

> В этой песочнице нет Android SDK, а домен `dl.google.com` (Google Maven,
> откуда качаются AGP/Compose/Room) недоступен через прокси — поэтому
> собрать и прогнать модуль `:app` здесь не получилось. Плагины
> Android/KSP объявлены только в `app/build.gradle.kts` (а не в корневом
> `build.gradle.kts` через `apply false`), а `org.gradle.configureondemand=true`
> в `gradle.properties` не даёт Gradle конфигурировать `:app` при сборке
> других модулей — поэтому `:domain/` — чистый Kotlin/JVM без
> Android-зависимостей — собирается и тестируется прямо здесь, не трогая
> Google Maven вообще (`./gradlew :domain:test`, 13/13 тестов зелёные), и
> это подтверждает корректность портированной логики расчёта. UI-слой
> (`:app`) нужно собрать и проверить в Android Studio или на CI с Android
> SDK.

### Установка на телефон

Проще всего — через GitHub Actions (`.github/workflows/android-build.yml`),
который на каждый push собирает debug-APK:

1. На GitHub откройте вкладку **Actions** → выберите последний прогон
   workflow **Android build** для нужной ветки.
2. В разделе **Artifacts** внизу страницы скачайте `app-debug-apk.zip`
   и распакуйте — внутри `app-debug.apk`.
3. Перекиньте APK на телефон (по кабелю, через облако/мессенджер и т.п.).
4. На телефоне откройте файл APK. Если Android спросит про установку
   из неизвестных источников — разрешите для приложения-файлового
   менеджера/браузера, которым открываете файл (Настройки → Приложения →
   Особый доступ → Установка неизвестных приложений).
5. Подтвердите установку — приложение появится как «Калькулятор ФОТ».

Это debug-сборка (не подписана релизным ключом) — для личного
использования подходит, но не годится для публикации в Google Play.

Альтернатива — собрать локально в Android Studio (`Build → Build APK(s)`)
или через `./gradlew :app:assembleDebug` на машине с Android SDK, и
установить полученный `app/build/outputs/apk/debug/app-debug.apk` тем же
способом, либо запустить прямо на подключённом по USB телефоне кнопкой
Run в Android Studio (нужен включённый режим отладки по USB).
